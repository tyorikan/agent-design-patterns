Key Changes

3つのクラスが1つの Workflow に統合

v2 では個別のオーケストレーションクラスが廃止され、宣言的なグラフ構文で全パターンを表現できるようになった

⛓️

チェーンタプル

SequentialAgent(sub_agents=[a, b, c])
↓
Workflow(edges=[("START", a, b, c)])

ノードをタプルで並べるだけで直列実行を表現。エッジが暗黙的に自動生成される。

🔀

ネストタプル

ParallelAgent(sub_agents=[a, b, c])
↓
Workflow(edges=[("START", (a, b, c), agg)])

タプルをネストすることで fan-out / fan-in パターンを宣言的に表現。

🔄

条件付きサイクル

LoopAgent(sub_agents=[a, b], max_iterations=5)
↓
Workflow(edges=[("START", a, b, {"REVISE": a})])

dict で条件分岐を定義。無条件サイクルは禁止。

コード構文の Before / After

Lv.3

Sequential — 直列実行

● v1 — SequentialAgent
from google.adk.agents import SequentialAgent

root_agent = SequentialAgent(
    name="etl_pipeline",
    sub_agents=[
        extract_agent,
        transform_agent,
        load_agent,
    ],
)
● v2 — Workflow チェーンタプル
from google.adk.workflow import Workflow

root_agent = Workflow(
    name="etl_pipeline",
    edges=[
        ("START", extract, transform, load),
    ],
)
Lv.4

Parallel — 並列実行 (fan-out / fan-in)

● v1 — ParallelAgent
from google.adk.agents import ParallelAgent

root_agent = ParallelAgent(
    name="multi_source",
    sub_agents=[
        web_researcher,
        tech_researcher,
        finance_researcher,
    ],
)
● v2 — Workflow ネストタプル
from google.adk.workflow import Workflow

root_agent = Workflow(
    name="multi_source",
    edges=[
        ("START",
         (web, tech, finance),  # fan-out
         aggregator),             # fan-in
    ],
)
Lv.5

Loop — 条件付きサイクル

● v1 — LoopAgent
from google.adk.agents import LoopAgent

root_agent = LoopAgent(
    name="code_gen_loop",
    sub_agents=[
        code_generator,
        code_tester,
    ],
    max_iterations=5,
)
● v2 — Workflow 条件付きエッジ
from google.adk.workflow import Workflow

root_agent = Workflow(
    name="code_gen_loop",
    edges=[
        ("START", generator, tester,
         {"FAIL": generator}),  # 条件付き
    ],
)

⚠️ Breaking Changes

注意すべき破壊的変更

v2 移行で発見した重要な差分と回避策

🚫

無条件サイクル禁止

v1 の LoopAgent は暗黙的にループしたが、v2 では無条件サイクルは ValidationError になる

❌ edges=[("START", a, b, (b, a))]

❌ LlmAgent(sub_agents=[Workflow(...)])
✅ Workflow(edges=[("START", coordinator, ...)])

❌ LlmAgent(sub_agents=[Workflow(...)])
✅ root_agent = Workflow(edges=[...])

v2 alpha/beta は PyPI staging index に公開される場合があり、uv sync でエラーになることがある

🔗

edges のチェーンタプル構文

edges リスト内の各タプルは ("START", ...) で始まる必要がある。複数チェーンは複数タプルで表現

edges=[("START", a, b, c)]
# 1タプル = 1チェーン

📌 付録 A: state_delta タイミング問題 深掘り

▼

根本原因

  • → output_key → state_delta → session.state への反映タイミングが非同期
  • → Sequential Workflow では問題なし（直列のため state が確定済み）
  • → Parallel Workflow（ネストタプル）で発生：複数ノードが同時に state を書き込む

解決策

instruction を callable にして ReadonlyContext.state.get() で動的に参照する

● Before — 静的参照（🔴 NG）
# instruction が定義時に評価される
instruction=f"data: {state['raw_data']}"
# → Parallel では未確定の state を参照してしまう
● After — callable 参照（✅ OK）
# 実行時に動的に state を取得
instruction=lambda ctx: (
    f"data: {ctx.state.get('raw_data', '')}"
)
# → 実行時点で確定済みの state を参照
