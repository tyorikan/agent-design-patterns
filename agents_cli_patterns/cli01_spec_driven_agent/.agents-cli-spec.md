# Spec: SLO Diagnostics & Runbook Agent (`cli01-spec-driven-agent`)

## 1. 目的（Why）
SRE / オンコール担当者がアラート発報時に「残りのエラーバジェット（許容障害時間）」と「標準復旧手順（Runbook）」を 1 回の対話で正確に把握できるようにする。LLM の暗算ミスを防ぐため、数値計算はすべて決定論的な Python ツールに委譲する。

## 2. 対象ユーザー（Who）
- Web サービスや API 基盤を運用する SRE・バックエンドエンジニア

## 3. スコープ定義（Scope & Non-Goals）
- **対応する処理（In Scope）**:
  - 月間（30日間 = 43,200分）の SLO 目標値（%）と累計ダウンタイム（分）からの残余エラーバジェット算出
  - 症状カテゴリ（`latency`, `error_rate`, `memory_pressure`, `cold_start`）に対応する一次切り分け Runbook の検索
- **対応しない処理（Out of Scope / 拒否条件）**:
  - 本番環境に対する再起動・ロールバック・設定変更コマンドの直接実行（常に人間が確認して実行する手順の提示に留める）
  - 推測による SLO 数値の捏造

## 4. ツール契約（Tool Contracts）
1. `calculate_error_budget(slo_target_percent: float, consumed_downtime_minutes: float, window_days: int = 30) -> dict`
   - 入力検証: `0 < slo_target_percent < 100`, `consumed_downtime_minutes >= 0`, `window_days > 0`
   - 出力: 許容総分数、消費率（%）、残余分数、ステータス（`HEALTHY` / `WARNING` / `EXHAUSTED`）
2. `lookup_runbook(symptom_category: str) -> dict`
   - 入力検証: 定義済みカテゴリ以外は例外停止させず、利用可能なカテゴリ一覧と再呼び出し方法を辞書で返す（構造化エラーフィードバック）

## 5. 受け入れ基準（Acceptance Criteria）
1. SLO 99.9%・消費 30 分の問い合わせに対し、`calculate_error_budget` を呼び出し、許容 43.2 分・残り 13.2 分・消費率 69.4% と正確に回答できること。
2. 本番ロールバックの直接実行を求められた場合、実行権限を持たない旨を明示して手順案内のみを行うこと。
